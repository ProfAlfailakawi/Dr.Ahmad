أولاً: رفع السيرة الذاتية PDF
--------------------------------
اسم المستند لا يلزم أن يكون متطابقاً مع أي اسم محدد.
يمكن اختيار ملف PDF عربي أو إنجليزي بأي اسم، مع مسافات أو حروف عربية.
يتحقق الموقع من أن محتوى الملف PDF حقيقي عبر توقيع الملف نفسه، وليس من الاسم أو الامتداد وحدهما.
بعد الرفع يحفظ الموقع النسخة العربية داخلياً باسم ثابت cv.pdf، والنسخة الإنجليزية باسم cv-en.pdf؛ ثم يستبدل رابط التنزيل في الموقع تلقائياً.

السبب الجذري الذي تمت معالجته:
كان ملف storage.rules موجوداً، لكن مسار GitHub Actions كان ينشر Firestore Rules فقط ولا ينشر Storage Rules. لذلك كان الرفع يُرفض من الخادم حتى مع ملف PDF صحيح واسم صحيح.
تم تعديل مسار النشر ليشمل:
--only firestore:rules,storage
وبذلك تُنشر قواعد التخزين تلقائياً عند رفع الملفات إلى GitHub، مع استمرار نشر الموقع حتى لو تعذر نشر القواعد وظهور تحذير واضح في سجل GitHub.

تحسينات الرفع:
- تحديث صلاحية المشرف قبل كل رفع وفحص admin claim.
- التحقق من توقيع PDF الحقيقي %PDF-.
- عدم الاعتماد على اسم المستند أو امتداده.
- فرض contentType: application/pdf.
- استخدام حاوية Firebase الافتراضية من إعداد المشروع.
- تقدم رفع حقيقي ورسائل خطأ مفهومة.
- عدم حفظ رابط ناقص عند فشل الرفع.

ملاحظة تشغيلية صادقة:
إذا استمر الخطأ بعد نشر هذه الحزمة، فالسبب ليس اسم الملف. افحص سجل GitHub Actions للتأكد من نجاح خطوة Deploy Firestore and Storage rules، وتأكد من أن Firebase Storage مفعّل للمشروع drahmad-8e9e2 وأن حساب خدمة النشر يملك صلاحية نشر القواعد. تفعيل حاوية أو خطة Firebase نفسها إجراء داخل حساب Firebase ولا يمكن للكود تفعيله نيابةً عن مالك المشروع.
