# استضافة مواد الأرشيف الصوتية

لا تُحفظ ملفات الصوت داخل المستودع أو ملف المشروع. تبقى الواجهة خفيفة، ويحمّل المتصفح الصوت مباشرة من التخزين الخارجي عند الضغط على التشغيل.

## الإعداد المعتمد

1. ارفع الملفين إلى المسار نفسه في التخزين المستخدم حاليًا، ويفضل Firebase Storage أو نطاق CDN مرتبط به:
   - `Tarbawyah-14.mp3`
   - `idaa.mp3`
2. اجعل الملفين قابلين للقراءة العامة فقط، من دون صلاحية كتابة عامة.
3. أضف رابط المجلد، لا رابط كل ملف، إلى متغير البيئة:

```env
VITE_MEDIA_AUDIO_BASE_URL=https://YOUR_AUDIO_CDN_OR_STORAGE_PATH
```

يركب الموقع الرابط النهائي من `audioFile`، فلا تدخل الملفات الكبيرة في Git أو Google AI Studio أو حزمة البناء.

## ضغط الملفات قبل الرفع

للحديث الإذاعي يكفي MP3 أحادي القناة بمعدل 64–80 kbps. هذا يحافظ عادة على وضوح الكلام ويخفض الحجم كثيرًا مقارنة بملفات WAV أو التسجيل عالي المعدل.

```bash
ffmpeg -i input.wav -vn -ac 1 -ar 44100 -b:a 72k output.mp3
```

للملف الموجود أصلًا بصيغة MP3 مرتفعة المعدل:

```bash
ffmpeg -i input.mp3 -vn -ac 1 -ar 44100 -b:a 72k output.mp3
```

استمع إلى الناتج كاملًا قبل استبدال الملف الأصلي. احتفظ بالنسخة الأصلية خارج المستودع كنسخة أرشيفية.

## سلوك الواجهة

- عند وجود الرابط يظهر مشغل صوت HTML خفيف مع `preload="metadata"`، فلا ينزل الملف كاملًا عند فتح الصفحة.
- عند غياب الرابط لا تظهر المساحة السوداء القديمة؛ تظهر رسالة صغيرة فقط.
- عند توفر التفريغ الزمني ينتقل المشغل إلى الثانية المطلوبة دون تشغيل تلقائي.
- لا يظهر حقل «الفهرسة» إذا لم يوجد تفريغ فعلي.
